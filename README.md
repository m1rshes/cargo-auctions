# Грузовые аукционы — SPA

SPA для работы с грузовыми аукционами (список, детальная страница, история ставок, установка ставки). Backend не используется — все данные и мутации обслуживает MSW.

## Стек

React 19, TypeScript, Vite, TanStack Router (file-based, с типизированными search params), TanStack Query, React Hook Form + Zod, MSW (`msw/browser`), Zustand (точечный клиентский UI-state), Tailwind CSS v4. Архитектура — Feature-Sliced Design.

## Запуск

```bash
npm install
npm run dev
```

Откройте адрес из вывода Vite (обычно `http://localhost:5173`). MSW-воркер стартует автоматически перед монтированием приложения (`src/main.tsx`) — бэкенд не требуется.

Другие команды:

```bash
npm run build     # tsc -b && vite build — типы + прод-сборка
npm run preview   # предпросмотр прод-сборки
npx vitest run    # unit-тесты
```

## Структура (Feature-Sliced Design)

```
src/
  app/        — точка входа, роутер (file-based routes), провайдеры, глобальные стили
  pages/      — страницы, собирающие виджеты под конкретный роут
  widgets/    — самостоятельные блоки UI (список, фильтры, карточка, форма ставки, таблица ставок)
  features/   — бизнес-функции (set-bid, filter-auctions) — модели, схемы, точечный UI-state
  entities/   — доменные сущности (auction, bet, city): API-вызовы, React Query хуки, ViewModel-мапперы
  shared/     — API-клиент, UI-кит, конфиг, MSW-моки (хендлеры + мутируемый in-memory store)
```

## Маршруты

- `/auctions` — список аукционов (фильтры синхронизированы с URL search params через Zod-схему)
- `/auctions/:auctionUuid` — детальная карточка (вкладки «Обзор» / «Ставки»)
- `/auctions/:auctionUuid/bets` — история ставок
- `/auctions/:auctionUuid/bid` — режим установки ставки, открывается по прямой ссылке

## Что именно реализовано

- Пагинация, skeleton/empty/error-состояния, prefetch детальной страницы по hover/intent (через `defaultPreload: 'intent'` роутера)
- Фильтры: `cargo_num`, `status`, `statuses`, `auc_type`, `load_city`/`unload_city` (мок-словарь городов), диапазон дат погрузки, `is_available`, `is_bidder`, диапазон цены — все в URL, с Zod-валидацией и безопасными fallback-значениями при повреждённых query-параметрах
- Primary action карточки аукциона: «Сделать ставку» / «Изменить ставку» / «Смотреть ставки» / disabled — по чистой функции-мапперу `getPrimaryAction`
- Детальная страница учитывает DTO-ограничения: `can_set_bet`, `hide_bets_history`, `hide_points_address_and_contacts`, `no_view_cargo_price`
- Форма ставки: RHF + Zod, динамическая схема на основе `min`/`max`/`step` из detail DTO, обработка 422 с привязкой ошибок к полю, success/error toast, инвалидация `list`/`detail`/`bets` после успешной мутации
- MSW-store реально мутирует состояние: после ставки пересчитывается текущая цена, статус пользователя (`Leading`/`Losing`), список и ранги ставок
- Точечный клиентский UI-state на Zustand: сворачивание панели фильтров (сознательно не в URL — это не адресуемое состояние страницы)

## Как проверялось

- `npx tsc --noEmit` по обоим tsconfig (app + node) — без ошибок
- `npm run build` — прод-сборка проходит без ошибок и предупреждений о неразрешённых импортах
- `npx vitest run` — 25 unit-тестов, все зелёные (см. раздел «Тесты»)
- Ручной обзор кода на соответствие контракту OpenAPI-фрагмента из задания: сверены названия и типы полей `restrictions`, `trading`, структура ответа `/auctions/list` и `/auctions/{uuid}/bets`
- **Не выполнялась** проверка в реальном браузере (нет доступа к headless-браузеру в среде разработки, где собирался проект) — это самое слабое место проверки, см. `AI_USAGE.md`, раздел «Риски»

### Сценарии, которые стоит пройти вручную при ревью

1. Открыть `/auctions`, применить несколько фильтров — убедиться, что они попадают в URL и переживают перезагрузку страницы
2. Ввести в адресную строку заведомо битые search params (например, `?page=abc&status=xyz`) — приложение должно откатиться к дефолтам, а не упасть
3. На карточке с доступной ставкой перейти по ссылке «Сделать ставку», отправить форму — проверить toast, редирект на детальную страницу и обновление текущей цены/статуса
4. Отправить ставку с ценой вне `min`/`max` — должна сработать клиентская Zod-валидация; если её обойти (например, временно ослабив схему), сервер (MSW) должен вернуть 422
5. Открыть аукцион с `hide_bets_history: true` — на вкладке «Ставки» должно показываться сообщение о скрытой истории, а не пустой список
6. Проверить mobile-раскладку (сужение окна) — карточки, фильтры и таблица ставок должны адаптироваться

## Ограничения / что осталось за рамками

- Локализация чисел/дат — только `ru-RU`, вариант на другую локаль не предусмотрен
- Нет персистентности фильтров в `localStorage` — выбран вариант с URL search params (это единственный источник правды для списка)
- Тесты покрывают только чистую логику (search params, request builder, мапперы, схема валидации ставки) — компонентных/интеграционных тестов нет
